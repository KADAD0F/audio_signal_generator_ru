# audio_signal_generator_ru

#ВНИМАНИЕ: 
В ТЕКУЩЕЙ РЕАЛИЗАЦИИ НАЙДЕНЫ КРИТИЧЕСКИЕ НЕДОРАБОТКИ ПРИ ГЕНЕРАЦИИ В MP3 ФОРМАТЕ, ПОЖАЛУЙСТА ПОДОЖДИТЕ НЕМНОГО, И Я ВЫЛОЖУ ИСПРАВЛЕННЫЙ СКРИПТ

Этот скрипт предназначен для генерации и сохранения различных типов аудиосигналов в популярных форматах (WAV, MP3, CSV), с возможностью визуализации и поддержкой стереофонического звука. Он автоматически определяет окружение (включая Termux на Android), устанавливает недостающие зависимости и адаптируется под ограничения системы.

---

## 🧩 Поддерживаемые типы сигналов

- **Синусоида (`sin`)** — чистый тон заданной частоты.
- **Амплитудная модуляция (`am`)** — несущая частота, модулированная по амплитуде.
- **Импульсный сигнал (`pulse`)** — прямоугольные импульсы с заданной скважностью (меандр).
- **Белый шум (`noise`)**:
  - `uniform` — равномерное распределение;
  - `normal` — нормальное (гауссово) распределение.
- **Частотная модуляция (`chm`)**:
  - `linear` — линейная ЧМ (линейное изменение частоты);
  - `quadratic` — квадратичная ЧМ;
  - `hyperbolic` — гиперболическая ЧМ.
- **Мульти-режим (`multi`)** — суммирование нескольких сигналов разных типов в один выходной файл.

---

## 📁 Сохранение результатов

Поддерживаются следующие форматы:

- **WAV** — без потерь, 16-бит PCM, совместим со всеми аудиопрограммами.
- **MP3** — сжатый формат (требуется `ffmpeg` и библиотека `pydub`).
- **CSV** — текстовый формат для анализа сигнала в Excel, Python, MATLAB и др.
- **Визуализация** — график сигнала в форматах PNG, SVG или PDF (первые 10 000 отсчётов для производительности).

## ⚙️ Особенности работы

### 🌐 Автоматическое определение окружения
- Обнаруживает **Termux** (Android-терминал) и предлагает корректный путь для сохранения файлов (`~/storage/shared`).
- При отсутствии прав на запись в Termux запускает `termux-setup-storage` и повторно проверяет доступ.

### 🔌 Управление зависимостями
- При отсутствии необходимых библиотек (`numpy`, `jax`, `librosa`, `pydub`, `matplotlib` и др.) скрипт:
  - Проверяет наличие интернета;
  - Запрашивает разрешение на установку;
  - Выполняет установку через `pip` с прогресс-баром для «тяжёлых» пакетов (например, `jax`, `librosa`);
  - Поддерживает альтернативные реализации (например, `jax.numpy` вместо `numpy`).

### 🛡️ Безопасность и надёжность
- Все имена файлов санитизируются: недопустимые символы заменяются, длина ограничена 255 символами.
- Сигналы автоматически нормализуются до уровня **0.99** для предотвращения клиппинга.
- Проверяется свободное место на диске перед генерацией больших файлов.
- Обработка прерываний (Ctrl+C) корректно завершает установку и генерацию.

### 📊 Ввод параметров
- Поддержка значений по умолчанию.
- Валидация диапазонов (например, частота ≤ половины частоты дискретизации).
- Возможность указания параметров отдельно для левого и правого каналов в стерео-режиме.

## ⚙️ Требования

Для корректной работы скрипта необходимы следующие компоненты:

### 🐍 Основа
- **Python 3.6 или новее** — скрипт использует современные возможности языка (f-строки, типизация и др.).

### 🌐 Сетевые возможности
- **Доступ в интернет** — требуется только при первом запуске или при отсутствии необходимых библиотек. Используется для автоматической установки зависимостей через `pip`.

### 📦 Обязательные системные зависимости
- **`ffmpeg`** — *только если требуется экспорт в MP3*.  
  FFmpeg — это мощный мультимедийный фреймворк, способный декодировать, кодировать, транскодировать, мультиплексировать, демультиплексировать, стримить, фильтровать и воспроизводить практически любые медиафайлы.  
  Установка:
  - **Ubuntu/Debian**: `sudo apt install ffmpeg`
  - **Fedora/RHEL**: `sudo dnf install ffmpeg`
  - **Windows**: загрузите исполняемый файл с [официального сайта](https://ffmpeg.org/download.html) и добавьте его в `PATH`
  - **macOS**: `brew install ffmpeg`
  - **Termux**: `pkg install ffmpeg`

### 📚 Python-библиотеки (устанавливаются автоматически при необходимости)

Скрипт автоматически определяет отсутствующие библиотеки и предлагает их установить. Поддерживается несколько уровней резервирования:

#### 1. **Библиотеки для работы с числовыми массивами** (обязательны)
- **`numpy`** — основная библиотека для научных вычислений в Python. Используется для генерации и обработки сигналов.
- **Альтернатива**: **`jax`** (включая `jax.numpy`) — если `numpy` недоступен, скрипт попытается установить `jax`, который предоставляет совместимый API.  
  ⚠️ Установка `jax` в Termux может занять **10–60 минут** и требует значительных ресурсов.

#### 2. **Аудиобиблиотеки** (для чтения/записи/анализа)
- **`pydub`** — используется для экспорта в MP3 (требует `ffmpeg`). Лёгкая и удобная обёртка над аудиообработкой.
- **`librosa`** — продвинутая библиотека для анализа аудиосигналов. Устанавливается как резерв при отсутствии `pydub`. Требует `numpy` и может быть «тяжёлой».
- **`soundfile`** — альтернатива для чтения/записи аудио в форматах WAV, FLAC и др. Лёгкая и быстрая.

#### 3. **Библиотеки визуализации** (опционально, только при запросе графика)
- **`matplotlib`** — стандартная библиотека для построения графиков. Работает в фоновом режиме (`Agg` backend), что делает её совместимой с Termux и серверами без GUI.
- **`plotly`** — интерактивная визуализация (в браузере). Устанавливается при отсутствии `matplotlib`.
- **`plotext`** — терминальная визуализация (графики прямо в консоли). Самый лёгкий вариант, используется как последний резерв.

> 💡 Все библиотеки устанавливаются через `pip`. Скрипт корректно обрабатывает прерывания (Ctrl+C) и выводит понятные сообщения об ошибках.

### 📱 Особенности на Android (Termux)
- Требуется разрешение на доступ к общему хранилищу. При первом запуске скрипт автоматически предложит выполнить `termux-setup-storage`.
- Некоторые «тяжёлые» пакеты (например, `jax`, `librosa`) могут компилироваться очень долго или не устанавливаться из-за ограничений архитектуры ARM и отсутствия оптимизированных wheel-файлов.
